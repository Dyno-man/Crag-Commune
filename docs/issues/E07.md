# Add constrained conversational planning and hard spending limits

## Outcome

Allow natural-language preferences while preserving deterministic planning and predictable operating costs.

## Scope

- [ ] Define typed parsing and explanation schemas and a replaceable provider adapter.
- [ ] Limit context to approved public catalog data and the necessary preferences.
- [ ] Validate all model-returned identifiers and treat retrieved text as untrusted.
- [ ] Add timeout, output, retry, per-user, and site-wide limits.
- [ ] Reserve request budget atomically before provider calls and settle measured usage afterward.
- [ ] Use revision-aware, privacy-scoped caching and fall back to structured planning.
- [ ] Evaluate realistic requests, ambiguous names, prompt injection, invalid IDs, outages, and concurrent budget use.

## Acceptance criteria

- [ ] No known closure violations or fabricated IDs are accepted in the evaluation suite.
- [ ] An exhausted budget or provider outage leaves core planning available.
- [ ] Concurrent requests cannot exceed the configured reservation cap.
- [ ] Private member messages and full profiles never enter model prompts.
