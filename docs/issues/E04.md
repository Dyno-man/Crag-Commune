# Build pseudonymous profiles and joinable climbing outings

## Outcome

Help a climber with few local connections find and join an outing with clear expectations.

## Scope

- [ ] Implement lightweight accounts, password recovery design, and pseudonymous profiles without identity or skill verification.
- [ ] Separate comfortable and project grades by discipline and permit optional availability and interests.
- [ ] Create area-filtered and date-filtered outing cards with capacity, join policy, meeting visibility, and time zone.
- [ ] Implement requested, accepted, declined, withdrawn, and waitlisted participation states.
- [ ] Support edits, cancellation, and in-app notifications for accepted participants.
- [ ] Default precise meetup details and participant lists to accepted participants.
- [ ] Test private-plan authorization and concurrent capacity updates.

## Acceptance criteria

- [ ] A new member can find an outing, request to join, and see appropriate details after acceptance.
- [ ] Public viewers cannot access private details through pages, APIs, or exports.
- [ ] Concurrent joins cannot exceed capacity or create duplicates.
- [ ] Cancellation and material changes are visible to participants.
